Key takeaways

  • Function calling lets models request tool calls with structured arguments that your code executes.
  • It equips chatbots with live data, actions and structured outputs, with matching security risks.
  • MCP standardises sharing tools, while function calling is the underlying model capability.
  • RAG supplies document knowledge, function calling reaches structured systems, and agents loop over both.
  • Agents can run offline with local models and tools, though small models call tools less reliably.

Function calling lets a language model request that your code run a specific function, such as searching a database or sending an email, by returning a structured call with arguments instead of plain text. It is the mechanism behind agentic AI. I build RAG and agent systems, so this page explains function calling in agents and chatbots, how it compares with MCP, RAG and agents, using it in Google AI Studio and LangChain, offline agents, and what calling a function means in Python.

What is function calling in agentic AI?

In agentic AI, function calling is how an agent acts: the model sees descriptions of available tools, decides which to call with what arguments, receives results, and continues reasoning until the task is done.

The loop is plan, call, observe, repeat. For example, a travel agent model might call search_flights, then check_calendar, then book_flight after confirmation. The model never executes code itself; your application runs each function and returns results. Reliability depends on clear tool descriptions, strict JSON schemas, input validation and limits on how many steps the agent may take. Sensitive functions should require human approval before execution.

What does function calling equip a chatbot with?

Function calling equips a chatbot with the ability to fetch live data and take actions: checking order status, booking appointments, querying databases, calling external APIs and performing calculations, beyond answering from its training data.

It also enables structured output: the model returns arguments in a defined JSON schema, which applications can validate and use reliably, for example extracting form fields from a message. This turns a conversational interface into a front end for real systems. The trade-off is risk: every function the chatbot can call is a capability that could be misused through prompt injection, so restrict permissions, confirm consequential actions with users, and log calls.

MCP vs function calling: what is the difference?

Function calling is the model capability: the model outputs a structured request to call a tool. MCP, the Model Context Protocol, is a standard for packaging and sharing tools, so any compatible application can discover and use them.

With plain function calling, each application defines its own tools in code and passes them to the model. With MCP, tools live in MCP servers, and clients such as Claude Desktop or Cursor list those tools and pass them to the model, which still uses function calling underneath. MCP adds discovery, reuse across apps and a common transport. For one app with a few tools, direct function calling is simpler; for shared integrations, MCP helps.

What is the difference between RAG and function calling?

RAG retrieves relevant text from documents and adds it to the prompt so the model can answer from it. Function calling lets the model request actions or data from external systems through defined tools.

They overlap: retrieval can itself be exposed as a function, so an agent decides when to search the knowledge base, which is agentic RAG. Classic RAG retrieves automatically on every question, while function calling lets the model choose. Use RAG for knowledge in unstructured documents, and function calling for structured data, transactions and actions, such as querying an order database. Many assistants combine both: search documents for policy and call functions for account-specific details.

What is the difference between function calling and an agent?

Function calling is a single capability: the model requests one or more tool calls in a response. An agent is a system built around that capability, running a loop of calls and observations, with memory, planning and stopping conditions.

Also asked as: difference between function calling and agent

A simple app might use function calling once, such as extracting structured data or calling a weather API, without being an agent. An agent repeatedly decides what to do next based on results, handling multi-step tasks like researching, comparing and acting. Agents add orchestration, error handling, state management and guardrails around function calling. Start with single function calls and move to an agent loop only when tasks require multiple dependent steps.

What is function calling in Google AI Studio?

In Google AI Studio, you can define function declarations, with names, descriptions and parameter schemas, and test how Gemini decides to call them. Gemini returns a function call with arguments, and you supply the function's response to continue.

AI Studio is a prototyping environment: experiment with prompts and tools there, then use the generated code with the Gemini API in Python or JavaScript, where your application executes the functions. Gemini supports parallel and compositional calls, and modes that force, allow or prevent function calls. Google's SDKs can also turn Python functions into declarations automatically. Test with realistic user requests to check that the model chooses the right functions and fills arguments correctly.

How do you implement OpenAI function calling with LangChain retrieval?

Wrap your retriever as a tool with a clear name and description, bind it to ChatOpenAI with bind_tools, and run an agent loop, for example with LangGraph, that executes tool calls and passes results back to the model.

Also asked as: how can implement function calling from openai with langchain retrieval

LangChain's create_retriever_tool turns a vector store retriever into a tool that returns relevant passages. Add other tools, such as a database lookup, so the model can choose between document search and structured data. Instruct the model to cite sources and to call the retriever before answering factual questions. Trace runs in LangSmith to see which tools were called and with what arguments, and evaluate answers on a test set to tune tool descriptions.

Can agentic AI function without the internet?

Yes, if the model and tools run locally. An agent built on a local open-weight model through Ollama or llama.cpp, with local tools such as file access, a local database and a local vector store, works fully offline.

Also asked as: can agentic ai function without internet

Many open models support function calling, including recent Llama, Qwen, Mistral and gpt-oss models, though smaller models call tools less reliably than frontier models. Offline agents suit privacy-sensitive environments, field work and air-gapped systems. They cannot browse the web or call cloud APIs, so design tools around local data. Test carefully with your chosen model, since tool-calling accuracy varies greatly, and add validation of every argument before execution.

What does calling a function mean in Python?

Calling a function means running its code by writing its name followed by parentheses and any arguments, such as greet("Asha"). Python executes the function body, then returns a value, or None if there is no return statement.

Defining a function with def only creates it; calling it executes it. Arguments can be positional or keyword, and functions can call other functions, including themselves, which is called recursion. In AI function calling, the model does not call Python functions directly; it outputs the function name and arguments, and your code performs the actual call. Understanding normal function calls makes this pattern easy to implement and debug.

What is the calling function and the called function?

The calling function, or caller, is the function that invokes another. The called function, or callee, is the one being invoked. For example, if main calls calculate_total, main is the caller and calculate_total is the callee.

Also asked as: what is calling function and called function

When the callee finishes, control returns to the caller along with any return value. Each call creates a new frame on the call stack holding its local variables, which is why deep recursion can cause stack overflow errors. A function that calls itself is recursive, acting as both caller and callee. Debuggers show the call stack, letting you trace which caller led to an error. The same caller and callee idea applies to APIs and agent tools.
