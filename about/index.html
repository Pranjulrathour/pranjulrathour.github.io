Pranjul Rathour is a GenAI engineer from Kanpur, Uttar Pradesh, who ships production AI systems: RAG pipelines, fine-tuned LLMs, hybrid retrieval and multi-modal apps across vision, speech and OCR, architected end to end from ingestion to deployment. 01 · Built

What has he built?

Five production AI applications at NextUpgrad Web Solutions between February and July 2026, each shipped end to end with Docker, CI/CD, structured logging and metrics.

RAG.NextUpgrad

Production RAG with hybrid dense + BM25 retrieval, re-ranking, streaming cited answers and a confidence gate that refuses weak-evidence answers. Runs in about 220 MB on a free tier.

View the code ↗

FineTune Studio

QLoRA fine-tuning from the browser with live training telemetry over WebSockets and base-vs-fine-tuned evaluation.

View the code ↗

DocuLens AI

Groq-powered invoice and contract extraction with schema validation and deterministic compliance scoring.

View the code ↗

FaceVision

Browser-only face detection, recognition and liveness with ONNX Runtime Web; the server stores embeddings, never images.

View the code ↗

OCR & Speech Workspace

Mistral-powered page-batched PDF OCR, live speech-to-text and document-scoped RAG chat with page citations.

View the code ↗

At SCULT INDIA, since 2024, he leads engineering, architecture, UI/UX, deployment and client delivery for a 14-member cross-functional team, and designed SCULT Studio CRM, the internal platform for projects, clients and operations. Earlier products include Vaidya AI, Annapurna, Super Digital Library and client sites for Nuclear Pest Goa, Gloss Digital Entertainment and Passionate Records. The full list is on the portfolio.

04 · Method

How does he write these pages?

Every page on this site starts from real search data and ends with cited sources.

The questions come from what people actually type into Google, Bing and YouTube and post on Stack Exchange, Hacker News and Dev.to, priced with Bing Webmaster Tools' measured impressions. The answers come from systems he built, documented in public repositories, and from primary sources: papers, official documentation and vendor pricing pages, linked at the end of each page. Facts about his own work come only from his verified profile. Pages are reviewed when the tools they describe change.
