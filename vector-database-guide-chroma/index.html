Vector database guide: vs embeddings, SQL, Elasticsearch, MCP, and Chroma in production

Key takeaways

  • Vector databases store embeddings with metadata and answer fast similarity queries.
  • Embedding models create vectors; vector databases make them searchable at scale.
  • SQL, Elasticsearch and vector databases complement each other, and pgvector combines SQL with vectors.
  • MCP can expose vector search as a tool for AI assistants.
  • Deploy Chroma in client-server mode with persistence, authentication, backups and pinned versions.

A vector database stores embeddings with their metadata and finds the most similar ones to a query quickly, which is how RAG systems fetch relevant passages for a language model. It complements, rather than replaces, embedding models, SQL databases and search engines. RAG.NextUpgrad combines dense vector retrieval with BM25, so this page explains vector databases, how they compare with embeddings, SQL, Elasticsearch and MCP, best practices, deploying Chroma in production, a Python tutorial, RAG examples and courses.

What is a vector database?

A vector database is a system designed to store vectors, such as text or image embeddings, along with metadata, and to answer nearest neighbour queries: given a query vector, return the most similar stored vectors quickly.

Also asked as: vector database explained

It combines an approximate nearest neighbour index, often HNSW, with database features: inserts, updates, deletes, metadata filters, persistence, replication and access control. In RAG, each chunk of a document becomes a vector with fields such as source, page and permissions; a question is embedded and the database returns relevant chunks in milliseconds. Many also support hybrid search, combining vector similarity with keyword scoring, which improves results for exact terms and names.

Embeddings vs vector database: what is the difference?

Embeddings are the vectors themselves, produced by an embedding model from text, images or other data. A vector database is where you store and search those embeddings. You need both: one creates representations, the other makes them searchable.

The embedding model determines quality: if it places similar meanings close together, search works well. The vector database determines speed, scale, filtering and reliability. Changing the embedding model requires re-embedding everything, while changing the database only requires migrating stored vectors and metadata. Some databases can call embedding models for you during insert and query, which blurs the line, but conceptually they remain separate components to choose and evaluate independently.

SQL vs vector database: which should you use?

SQL databases excel at exact queries, joins, transactions and structured data such as users, orders and permissions. Vector databases excel at similarity search over embeddings. Many applications need both, and PostgreSQL with pgvector can provide both in one system.

Use SQL for anything requiring exact matching or aggregation, such as finding orders by date or counting users. Use vector search for meaning-based retrieval, such as finding passages similar to a question. With pgvector, you can combine them in one query, filtering by tenant and date while ranking by similarity. Dedicated vector databases make sense at large scale or when you need advanced vector features, with your relational data remaining in SQL.

Elasticsearch vs vector database: how do they compare?

Elasticsearch is a search engine built on Lucene for full-text search, analytics and logs, and it now supports dense vector search with HNSW. Dedicated vector databases focus on vector workloads with simpler APIs and vector-specific features.

Elasticsearch shines when you need strong keyword search, aggregations, existing log or document pipelines, and hybrid retrieval in one engine, including reciprocal rank fusion. Dedicated vector databases can offer leaner operations, more vector-focused tuning and lower memory use for large embedding collections. OpenSearch, the open-source fork, offers similar capabilities. If your team already runs Elasticsearch for search, adding vectors there is often simplest; otherwise compare both on your data and filters.

MCP vs vector database: what is the difference?

They are different layers. A vector database stores and searches embeddings. MCP, the Model Context Protocol, is a standard for connecting AI assistants to tools and data. An MCP server can expose a vector database search as a tool.

For example, you might build a retrieval service over your company documents in Qdrant or pgvector, then wrap it in an MCP server with a search tool. Assistants such as Claude Desktop or Cursor can then call that tool to fetch relevant passages during conversations. Several vector database vendors publish MCP servers for this purpose. Choose a vector database for retrieval performance, and use MCP to make that retrieval available to many AI clients.

What are vector database best practices?

Store source text, document IDs, model version and metadata with every vector; index fields you filter on; choose the distance metric your embedding model expects; batch writes; and evaluate recall on real queries before tuning indexes.

More practices: separate tenants with metadata partitions rather than thousands of collections; use quantization to reduce memory for large collections, with rescoring for accuracy; keep vectors in sync when documents change by tracking content hashes; back up regularly and test restores; secure access with authentication and network rules; and monitor latency, memory and index build status. Combine vector search with keyword search and reranking for the best RAG quality.

How do you deploy Chroma in production?

Run Chroma in client-server mode rather than embedded in your app: deploy the official Chroma server Docker image with a persistent volume, enable authentication, and connect from your application with the HTTP client. Chroma Cloud is a managed alternative.

Also asked as: how to deploy chroma database (vector database) in production

Production checklist: mount durable storage for the data directory; put the server behind HTTPS and restrict network access; configure token-based authentication; set resource limits and monitor memory, since indexes live in memory; back up the persistent directory regularly; and pin the Chroma version, upgrading deliberately after reading migration notes. For large multi-tenant workloads or strict high-availability needs, compare Chroma with Qdrant, Weaviate, Milvus or pgvector before committing.

What is a good vector database tutorial in Python?

Start with Chroma or Qdrant's local mode: create a client, create a collection, add a few documents with metadata, then query with text and a metadata filter. Both run in a Python process without extra infrastructure.

Also asked as: vector database tutorial python

Example flow with Chroma: client = chromadb.PersistentClient(path="db"), then col = client.create_collection("notes"), col.add(ids=[...], documents=[...], metadatas=[...]), and col.query(query_texts=["your question"], n_results=3). Next, swap in your own embedding model, load real documents with chunking, and measure whether the right chunks come back for test questions. Then try the same with Qdrant or pgvector to compare. Each vendor's GitHub organisation provides complete notebooks for RAG, hybrid search and filtering.

What are vector database examples for RAG?

Common RAG setups include Chroma for prototypes, pgvector for apps already on PostgreSQL, Qdrant or Weaviate for self-hosted production with filtering and hybrid search, Pinecone for fully managed scale, and Elasticsearch or OpenSearch where keyword search already runs.

Example: a university handbook assistant stores chunks in pgvector with metadata for faculty and year, retrieves with hybrid search and reranking, and cites pages. Another: a support assistant uses Qdrant with tenant filters so each customer sees only their documents. A third: a legal tool uses Weaviate hybrid search to match exact clause numbers plus meaning. The database choice matters less than chunking, retrieval quality and evaluation, which decide answer accuracy.

What is a good vector database course?

Good options include DeepLearning.AI short courses on vector databases and semantic search, vendor learning hubs from Pinecone, Weaviate and Qdrant, and Hugging Face material on embeddings. Most are free and hands-on.

Also asked as: course vector database

Look for courses that cover embeddings, ANN indexes such as HNSW, metadata filtering, hybrid search, reranking and evaluation, not just inserting and querying vectors. Vendor courses teach their own APIs, so learn concepts that transfer between systems. After a course, build a small benchmark: index the same documents in two databases and compare recall, latency and memory. That exercise teaches more about trade-offs than any lecture and makes a strong portfolio piece.
