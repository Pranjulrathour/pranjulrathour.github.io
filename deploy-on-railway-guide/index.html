How to deploy on Railway: from GitHub, FastAPI, Django, Next.js, databases, n8n and bots

Key takeaways

  • Railway deploys apps from GitHub automatically, detecting the language and building with its builders or your Dockerfile.
  • Backends, frontends, workers, cron jobs and databases can all run as services in one Railway project.
  • Apps must listen on the PORT variable Railway provides and read secrets from environment variables.
  • Provision PostgreSQL, MySQL, Redis or MongoDB in a click and reference their connection variables.
  • Use pre-deploy commands for migrations; long-running bots run as services without a public domain.

To deploy a project on Railway from GitHub, create a Railway project, choose "Deploy from GitHub repo", select your repository, and Railway builds and deploys it automatically, redeploying on every push. It detects common languages and frameworks, or uses your Dockerfile, and lets you add databases and other services alongside. I deploy FastAPI and Next.js services regularly, so this page covers deploying from GitHub, backends, FastAPI, Django, Laravel, Next.js, databases, n8n, bots and deploy-time commands.

How do I deploy a project on Railway from GitHub?

Sign in to Railway with GitHub, create a new project, select "Deploy from GitHub repo", choose the repository and branch, add environment variables, and generate a public domain under the service's networking settings. Railway builds and deploys on each push to the branch.

Also asked as: how to deploy project on railway from github

Before deploying, make sure your app reads its port from the PORT environment variable and binds to 0.0.0.0, keeps secrets in environment variables rather than code, and has a clear start command. Railway's builders detect most Node, Python, Go, Java and PHP projects; for custom setups, include a Dockerfile, which Railway uses automatically. Watch the first build's logs closely: most failures come from missing dependencies, a wrong start command or an app listening on a fixed port instead of Railway's.

Can I deploy a backend on Railway?

Yes. Railway is well suited to backends: REST and GraphQL APIs, WebSocket servers, background workers and scheduled jobs, in languages such as Python, Node.js, Go, Java, Ruby and PHP, with databases in the same project.

Also asked as: can i deploy backend on railway · can i deploy nextjs on railway

Each service gets environment variables, logs, metrics and optional public or private networking. Services in a project communicate over a private network using internal hostnames, so your API can reach the database without exposing it publicly. Scale settings, health checks and restart policies help keep backends reliable. Railway is popular for hackathon and startup backends because setup takes minutes. Preview environments for pull requests let you test changes on a temporary copy before merging, which suits small teams without dedicated DevOps engineers.

How do I deploy FastAPI on Railway?

Push your FastAPI project with a requirements.txt to GitHub, deploy it on Railway, and set the start command to run Uvicorn on Railway's port, binding to all interfaces.

Also asked as: how to deploy fastapi on railway

uvicorn main:app --host 0.0.0.0 --port $PORT

Add environment variables for database URLs and API keys, generate a domain, and check the deployment logs. For production, run multiple workers or use Gunicorn with Uvicorn workers, add a health check endpoint, and keep secrets in Railway variables. If you use a database, reference its connection string variable instead of hard-coding credentials. For AI APIs, store provider keys as variables and stream responses, since Railway supports long-lived HTTP connections well.

How do I deploy Django on Railway?

Deploy the repository, set the start command to run Gunicorn with your project's WSGI module on Railway's port, configure allowed hosts and CSRF trusted origins for your domain, and run migrations and static file collection during deploys.

Also asked as: how to deploy django on railway

Checklist:

  • Add Gunicorn and a PostgreSQL driver to requirements.
  • Read SECRET_KEY, DEBUG and the database URL from environment variables.
  • Add the Railway domain to ALLOWED_HOSTS and CSRF_TRUSTED_ORIGINS.
  • Use WhiteNoise or object storage for static files.
  • Run python manage.py migrate as a pre-deploy command.
  • Set DEBUG to false in production.

Can Railway deploy Laravel?

Yes. Railway can build PHP and Laravel applications from GitHub, and provides guides and templates for Laravel with a database. Configure the start command, environment variables such as APP_KEY and database settings, and run migrations during deployment.

For Laravel, also plan for queues and scheduled tasks: run a separate worker service for php artisan queue:work, and a cron service for the scheduler. Store uploaded files in object storage rather than the container's filesystem, which is not persistent across deploys. Check Railway's Laravel guide for current builder settings and recommended configuration.

Can I deploy Next.js on Railway?

Yes. Railway builds Next.js apps from GitHub and runs them with next start, supporting server-side rendering, API routes and server actions. Set environment variables in Railway, and generate a public domain.

Railway is a good fit when your Next.js app needs a long-running server, WebSockets or a co-located database and backend in the same project. For purely static or edge-heavy Next.js sites, Vercel is the specialised alternative. For frontends built with Vite or other static frameworks, Railway can serve the built files with a static server, though static hosting platforms are often simpler.

How do I deploy a database on Railway?

In your project, click to add a new service and choose a database such as PostgreSQL, MySQL, Redis or MongoDB. Railway provisions it with persistent storage and exposes connection variables, which you reference in your app's environment variables.

Also asked as: how to deploy database on railway

Reference variables let services share credentials without copying them, for example setting your app's database URL to the database service's variable. Use the private network for app-to-database traffic. Set up backups, monitor storage usage, and avoid exposing the database publicly unless necessary. For pgvector-based RAG, choose a PostgreSQL image or template that includes the extension.

Can I deploy n8n on Railway?

Yes. Railway offers community templates that deploy n8n with PostgreSQL in a few clicks, configuring the database, volumes and environment variables. You can also deploy the official n8n Docker image yourself.

After deploying, set a fixed encryption key, configure the webhook URL to your Railway domain so webhooks work, enable authentication for the editor, and back up the database. For heavier workloads, use n8n's queue mode with Redis and worker services. Monitor usage, since long-running automations and frequent executions consume resources continuously.

How do I deploy a bot on Railway?

Deploy your bot's repository as a service with a start command that runs the bot, such as python bot.py or node index.js, and store the bot token in environment variables. Bots that poll for updates do not need a public domain.

Also asked as: how to deploy bot on railway

Discord, Telegram and Slack bots run continuously as worker services. If your bot uses webhooks instead of polling, generate a domain and register the webhook URL with the platform. Add a database for persistent data, set restart policies so crashes recover automatically, and check logs when the bot stops responding. Never commit tokens to GitHub. If a token leaks, revoke it immediately in the platform's developer settings and update the Railway variable.

What is a post-deploy step in Railway?

Railway supports a pre-deploy command, which runs after the build and before the new version starts receiving traffic, commonly used for database migrations. For work after deployment, such as cache warming or notifications, use your app's startup logic, a separate job service, or CI steps.

Also asked as: what is post deploy in railway

Pre-deploy commands are ideal for migrate steps: if the command fails, the deployment stops and the previous version keeps running, preventing broken releases. For recurring tasks, Railway's cron schedules run services on a timetable. Check the documentation for current deployment lifecycle options, since Railway regularly adds features.
